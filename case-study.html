Studi Kasus: IoT-Component-Manager

Menyelesaikan Kekacauan Inventaris Lab Kampus dengan Sistem Peminjaman Berbasis Web

Sebuah perjalanan rekayasa produk digital end-to-end (10 Minggu) untuk mengelola peminjaman sensor, mikrokontroler, dan modul IoT secara terstruktur dan efisien.

[Lihat Live Web] [Repositori GitHub]

Validasi Masalah & Riset Pengguna

Problem Statement: Proses peminjaman komponen IoT (seperti ESP32, Arduino, dan sensor) di laboratorium kampus masih dilakukan secara manual atau menggunakan pencatatan yang tidak terpusat. Hal ini menyebabkan komponen sering hilang, status ketersediaan tidak akurat, dan pelacakan riwayat peminjaman menjadi sangat sulit.

User Persona & Pain Points

  • Target Pengguna: Mahasiswa yang sedang mengerjakan proyek sistem tertanam dan Asisten Laboratorium.
  • Pain Points:
    • Mahasiswa harus datang ke lab hanya untuk mengecek ketersediaan komponen.
    • Asisten lab kewalahan mencatat tanggal pengembalian dan menagih komponen yang telat dikembalikan.
    • Tidak ada hitung mundur otomatis untuk tenggat waktu peminjaman.

Blueprint & Desain Antarmuka

Sebelum menulis kode, saya memetakan alur pengguna (*User Flow*) agar interaksi terasa natural dan tidak membingungkan.

Alur Utama (User Flow)

  1. Pengguna melakukan Login/Sign Up.
  2. Melihat *Dashboard* ringkasan dan daftar komponen yang tersedia.
  3. Mengajukan peminjaman komponen dan melihat status di menu "Peminjaman Saya".

Wireframe & Prototipe

Desain dibangun menggunakan Figma dengan mematuhi prinsip aksesibilitas. Saya menerapkan tag semantik HTML5 sejak awal perancangan untuk memastikan kerangka UI solid dan mudah diindeks oleh *screen reader*.

Pengembangan Kode & Integrasi Data Dinamis

Untuk memastikan performa aplikasi cepat dan pengelolaan data yang real-time, saya memilih tumpukan teknologi (*Tech Stack*) modern:

  • Frontend: HTML5 & Svelte (memberikan reaktivitas yang sangat cepat tanpa virtual DOM).
  • Backend/Database: Supabase (sebagai *BaaS* untuk autentikasi pengguna dan manajemen *database* relasional inventaris).
  • Deployment: Cloudflare (memastikan web dapat diakses cepat secara global dengan perlindungan keamanan bawaan).

Di fase ini, logika *CRUD* (Create, Read, Update, Delete) diimplementasikan, termasuk fitur hitung mundur waktu jatuh tempo pengembalian komponen.

Pengujian Pengguna & Kesiapan Rilis

Setelah web diluncurkan (*live*), saya melakukan *Usability Testing* menggunakan alat pelacak (*tracker*) untuk melihat interaksi pengguna secara nyata.

Hasil Iterasi (Before vs After)

Berdasarkan rekaman interaksi, beberapa pengguna kebingungan saat mencari letak tombol "Kembalikan" di tabel. Saya melakukan iterasi desain secara cepat (*sprint*) melalui *Pull Request* di GitHub.

Audit Performa (Core Web Vitals)

Aplikasi ini sangat ringan dan responsif, dibuktikan dengan skor Google Lighthouse yang menembus angka memuaskan (>85).

Checklist Keamanan Dasar

  • ✅ HTTPS Terenkripsi: Koneksi aman difasilitasi oleh Cloudflare.
  • ✅ Sanitasi Input: Formulir peminjaman dan pencarian aman dari injeksi script berbahaya.
  • ✅ Isolasi `.env`: Kunci API Supabase dan konfigurasi sensitif lainnya aman dan tidak bocor di repositori publik.
  • ✅ Privasi Data (PDP): Autentikasi yang ketat dan tidak mengumpulkan data pribadi di luar keperluan kampus.
