Fase 01 • Modul 1–3 Empirical Research

The Problem — Mengapa Sistem Manual Gagal?

Sebelum menulis sebaris kode pun, kami melakukan riset lapangan ke laboratorium Teknik Informatika untuk memetakan titik kegagalan sistem peminjaman konvensional.

🔍 Temuan Lapangan

Kekacauan Logistik Fisik di Laboratorium

Peminjaman komponen mikroprosesor (Arduino, ESP32, Raspberry Pi) dan ratusan modul sensor sebelumnya dicatat pada buku tulis manual. Ketika mahasiswa berbondong-bondong mengerjakan tugas akhir, asisten lab kewalahan memverifikasi siapa peminjam terakhir dan berapa unit yang masih sehat.

Akar Masalah: Asimetri informasi antara mahasiswa (tidak tahu komponen siap pakai) dan asisten lab (tidak punya riwayat pemeliharaan terstruktur).
👥 Target Pengguna

User Persona Dual-Stakeholder

Mahasiswa IoT Mencari ketersediaan modul cepat & pinjam fleksibel
Asisten Laboratorium Audit stok otomatis & tracking barang terlambat/rusak

5 Pain Points Kritis

  • × Mahasiswa harus mondar-mandir ke lab hanya untuk cek stok fisik.
  • × Catatan manual sering tercecer atau tak terbaca tulisan tangannya.
  • × Komponen rusak sering dikembalikan diam-diam tanpa verifikasi status.
  • × Tidak ada estimasi tanggal pengembalian yang transparan.
  • × Pencarian hardware memakan waktu hingga 15–20 menit per mahasiswa.

// RPC Supabase: Atomic Stock Check & Checkout
CREATE OR REPLACE FUNCTION checkout_component(
  p_item_id UUID, p_user_nim TEXT
) RETURNS JSON AS $$
BEGIN
  IF (SELECT stock FROM components WHERE id = p_item_id) > 0 THEN
    UPDATE components SET stock = stock - 1 WHERE id = p_item_id;
    INSERT INTO loans(item_id, nim, status) VALUES (p_item_id, p_user_nim, 'active');
    RETURN json_build_object('success', true);
  END IF;
  RETURN json_build_object('success', false, 'msg', 'Out of stock');
END; $$ LANGUAGE plpgsql SECURITY DEFINER;

Hasil Iterasi Berdasarkan Temuan User

Perbaikan 01

Koreksi Logika Sinkronisasi Ketersediaan Stok

Temuan Bug

Ketika sebagian unit dipinjam (misal 2 dari 5 unit), status katalog keliru menampilkan label oranye "Sedang Dipinjam" dan tombol CTA peminjaman terkunci mati, seolah-olah barang sudah habis total.

Solusi Iterasi

Merombak conditional rendering: Jika total stok berkurang namun masih ada sisa, status berubah menjadi "Sebagian Dipinjam" (Warna Biru Agak Gelap) dan tombol peminjaman (Biru Muda) tetap aktif!

Perbaikan 02

Alur Transparan Pelaporan Kerusakan Hardware

Temuan Bug

Pengguna yang mengembalikan komponen rusak tidak memiliki kanal keterangan di formulir, sehingga hardware rusak tercampur kembali ke wadah siap pakai.

Solusi Iterasi

Menambahkan tombol toggle interaktif "Laporkan Kendala Komponen" yang membuka textarea diagnosis dan otomatis memberi flag status "Perlu Servis" ke asisten lab.
